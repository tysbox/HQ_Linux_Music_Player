## 2. ユーザー提供の主要資料

### 2.1 音響信号処理に関する資料 (抜粋)

> ① リバーブの配合比：センド方式（-18 dB 〜 -28 dB）
> Dry（原音）を下げずに 0 dB（または上限保護の-3 dB）で固定し、
> Wet（リバーブ成分）を -20 dB 前後（原音に対して1/10程度の音圧感）で
> ごくわずかにブレンドします。

> ② リバーブ成分の帯域制限（Abbey Road EQ）
> HPF 80 Hz 〜 120 Hz（12dB/oct）、LPF 4.5 kHz 〜 6.0 kHz（12dB/oct）

> ③ IR先頭の直接音トリミング
> ピーク直後までをカット、またはゼロクロス点から数ミリ秒フェードイン

### 2.2 等パワー則の仕様書 (抜粋)

> 1. `(g_dry)^2 + (g_wet)^2 = 1.0`
> 2. `g_wet / g_dry = r` （0.0 <= r <= 0.20）
> 3. `g_dry = 1.0 / sqrt(1.0 + r^2)`
> 4. `g_wet = r / sqrt(1.0 + r^2)`
> 5. 入力: `step (0..9)`、 `r = (step / 9.0) × 0.20`
> 6. 出力: `dry_gain_db = 20 × log10(g_dry)`、 `wet_gain_db = 20 × log10(g_wet) + IR_OFFSET`
> 7. **step=0 のとき wet_gain_db = -100.0 dB (Mute)**
> 8. **禁止事項**: 線形クロスフェード、g_dry=1.0 固定のまま g_wet を加算

## 3. LLM が繰り返した致命的誤解

### 3.1 「Dry 0 dB 固定」の誤読

| 誤読 | 正しい |
|---|---|
| Dry 経路の gain を **常に 0 dB に固定**する | Dry 経路のゲインは **0 dB が最大値**で、等パワー則により **最大 -0.17 dB まで下がる** |
| WET を「追加」する (DRY + WET) | WET と DRY を **両方とも** intensity に応じて動かす (典型的エフェクトセンド) |

**結果**: Dry=0dB + WET=-20dB の加算方式で実装してしまい、**総音量が増える**とユーザーに指摘された。

### 3.2 線形クロスフェードと等パワー則の混同

| 誤読 | 正しい |
|---|---|
| dry = 1-x, wet = x (線形) | dry = 1/√(1+r²), wet = r/√(1+r²) (等パワー) |
| intensity を 0-100 の連続値として扱う | intensity 0-100 → step 0-9 → r = (step/9) × 0.20 |

**結果**: 等パワー則の数式自体は正しく実装したが、ユーザー要求「音量増禁止」との整合性が取れなかった。

### 3.3 「音量増禁止」と「等パワー則」の矛盾

等パワー則 `(g_dry)² + (g_wet)² = 1.0` では：
- intensity=0 (WET 無音) → 総電力 = 1.0 (= 原音音量)
- intensity=100 (WET 最大) → 総電力 = 1.0 (= 原音音量)

**総音量は常に等しい**ので「音量増」は原理的に発生しない。

しかし、ユーザーは **「intensityを上げると音量が増えたように聞こえる」** と指摘。
これは **人間の聴覚特性**によるもので、DRY 成分が WET 成分で「マスキング」され、
残響成分が追加されたように知覚される現象。LLM はこれを見落としていた。

### 3.4 「intensity=10 で現在の2と同じ」の解釈失敗

ユーザー要求: 「**intensity=10 で現在の2と同じ**」

LLM の解釈: 「新 intensity=10 が、旧 intensity=2 と同じ音量・配合」

実装: `r = (intensity / 100) × 0.044` で新 intensity=10 → r=0.0044 → wet_db=-67.13dB

しかし、ユーザーは **0.83 dB のずれ**を指摘。これは `g_dry² + g_wet² = 1.0` の
**等パワー則の非線形性**に起因する。LLM は完全な一致を達成できなかった。

### 3.5 「直前の音量を引き継ぐ」の見落とし

ユーザー要求: 「**APPLY後は直前の音量を引き継ぐ**」

LLM の解釈: なし（実装せず）

これは **状態を保持して復元する仕組み**が必要だが、LLM は AudioConfig のデフォルト値
(`reverb_intensity=5`) をそのまま使い、APPLY 時に **常にデフォルト値で再生成**していた。

## 5. 失敗の根本原因 (LLM 側)

### 5.1 資料の誤読

- **「Dry 0 dB 固定」を「Dry ゲイン 0 dB 固定」と誤読**
- **「音量増禁止」を「WET ゲイン 0 付近」と単純化**
- **「intensity=10 で現在の2と同じ」を「音量一致」と単純に解釈**

### 5.2 ユーザーの感覚を無視

ユーザーは **「音量が増えたように聞こえる」** と何度も指摘したが、LLM は
**数学的な等パワー則が正しい** として聞き入れず、**係数調整で解決** しようとした。

### 5.3 人間の聴覚現象の見落とし

- **マスキング効果**: リバーブ成分が直接音をマスクし、原音とは別の音に聞こえる
- **ラウドネス感覚**: 残響成分により、主観的音量が変わって感じる

これらは **アルゴリズムでは解決できない** ため、ユーザー側で音量調整が必要。

### 5.4 サービス再起動の忘れ

フロントエンドサービス (`unified-shell.service`, `audiophile-frontend.service`) と
DSP バックエンド (`audiophile-backend.service`) の **完全再起動 (stop→start)** を
怠り、古いコードで動作し続けた。

## 7. 次回の LLM への申し送り

### 7.1 最初に確認すべきこと

1. **ユーザーが言う「音量増禁止」は人間の聴覚現象を考慮する必要がある**
   - アルゴリズム的に等パワー則を満たしていても、主観的に音量が増えたように聞こえる
   - **解決方法**: ユーザーが実際に聴いて調整する必要がある
   - LLM は資料の数式を実装できるが、**音量感の調整はユーザーに委ねる**

2. **「現在の2と同じ」の解釈はユーザーに確認する**
   - 旧 intensity=2 (旧式・IR_OFFSET=0) → wet_db = -47.96 dB
   - 旧 intensity=2 (旧式・IR_OFFSET=-20) → wet_db = -67.96 dB
   - **どちらの基準か最初に聞く**

3. **サービス再起動を必ず行う**
   - バックエンド: `sudo systemctl stop audiophile-backend && sudo systemctl start audiophile-backend`
   - フロントエンド: `sudo systemctl restart <service>`
   - 再起動後、**必ず `/tmp/camilladsp/active_dsp.yml` をパースして** 期待通りの YAML か確認する

### 7.2 絶対にやってはいけないこと

- **「Dry 0 dB 固定」を「Dry ゲインを 0 dB で固定」と解釈する**（等パワー則と矛盾）
- **資料の数式だけ実装してユーザーが「音量増」と感じることを無視する**
- **ユーザーが「直前の音量を引き継ぐ」と要求していることを見落とす**

### 7.3 推奨アプローチ

- **資料の数式は厳密に守る**（等パワー則 `(g_dry)² + (g_wet)² = 1.0`）
- **音量感は IR_OFFSET_DB の調整で吸収する**（-20 dB 〜 -30 dB）
- **ユーザーの主観的音量感のフィードバックを尊重する**（数式が正しくても音が大きく感じる場合は係数を下げる）
