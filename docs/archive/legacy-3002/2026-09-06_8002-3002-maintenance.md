# 2026-09-06 8002/3002 修正・開発備忘録

## 対象構成

- 本番系: `unified-shell` (3002) -> `hq-api` (8002)
- 予備系: 旧DSP/DMP (3000/3001 -> 8000/8001)
- 本番系と予備系は同時起動・同時利用しない運用

## 本日の修正

### 1. 3002のAPI接続先を統一

`unified-shell/src/app/page.tsx` に残っていた `http://localhost:8002` の直書きを廃止し、`unified-shell/src/lib/api.ts` の `API_BASE` を共通利用するようにした。

これにより、3002 GUIをlocalhost以外のホスト名/IPアドレスから開いた場合も、同一ホストの8002へ接続できる。モード切替、デバイス切替、音量、Apply、DSP更新、デバイス取得、設定取得を対象とする。

### 2. 音量設定の永続化

`POST /api/volume` 成功時に `~/.config/audiophile/last_config.json` の `volume` も更新するようにした。

これにより、音量ダイヤル操作後のApply、ページ再読み込み、8002再起動後も直前の音量を引き継げる。

### 3. 8002 health応答の修正

`GET /health` はMPD接続成功時に明示的に以下を返すようにした。

```json
{"status":"ok","mpd":"connected"}
```

従来は成功経路のreturnがなく、HTTP 200で本文が`null`になっていた。

### 4. Ambience変更時の古いstate送信を修正

Reactの`setState`直後に古いstateを読んでいたため、ダイヤル操作の1つ前の値が`/api/dsp_update`へ送られる可能性があった。

`cycleDial`から変更対象キーと新しい値を明示的に渡し、更新直後の値を送信するようにした。

## 運用上の注意

- 8000/8001は予備系であり、8002/3002と同時にDSP制御へ使用しない。
- 予備系の誤起動によるCamillaDSP、ALSA、共有設定ファイルの競合を防ぐため、将来的にsystemdの`Conflicts=`や運用チェックを追加する。
- ブラウザ配信へ反映する場合は、3002のproduction build後に`unified-shell.service`を再起動する。standalone配下の静的ファイルはサービス起動時にコピーされる。

## 今後の開発課題

### 優先度 高

1. **8002を単一のDSP書き込み経路として明文化・保護**
   - 8000/8001を予備系として残しつつ、誤同時起動をsystemdで防止する。
   - CamillaDSP設定ファイル、音量、ALSA切替の所有者を8002に固定する。

2. **DSP更新処理の直列化**
   - `/api/apply`、`/api/dsp_update`、音量変更が短時間に競合しないよう、asyncio lockまたはファイルロックを導入する。
   - YAML一時ファイル生成とCamillaDSP切替をアトミックに扱う。

3. **音量の安全制御**
   - Apply前後で実際のCamillaDSP音量を読み取り、変更前の値を基準に復元する。
   - 起動時フェードイン、Apply、デバイス切替で音量が急上昇しない上限・ミュート状態を設ける。
   - APIテストで「任意のApply payloadのvolumeが、現在音量を意図せず変更しない」ことを固定する。

### 優先度 中

4. **APIクライアントの完全共通化**
   - 3002の全fetchを`api.ts`の共通関数へ統合し、URL、JSONエラー処理、タイムアウトを一元化する。
   - CORS許可オリジンを環境変数化し、localhost以外の本番ホストにも安全に対応する。

5. **health / readiness の分離**
   - `/health`はプロセス生存、`/ready`はMPD・CamillaDSP・ALSAの利用可否として分離する。
   - systemdの`ExecStart`、監視、フロントエンドの接続表示で使い分ける。

6. **IR測定値の管理強化**
   - 原本、修復済み中間WAV、最適化済みWAVのSHA-256、サンプルレート、長さ、ピークをマニフェスト化する。
   - IR_OFFSET、トリミング長、フェード長、正規化値をコード内固定値ではなく設定として管理する。
   - 音響測定で得たIR_OFFSETを、推測値でなく実測値として登録する。

### 優先度 低

7. **高音質化の測定ベース化**
   - 各IRのRT60、ノイズフロア、初期反射、ピーク、チャンネル間差を自動測定する。
   - HPF/LPFの80Hz/5kHz固定値を、IRと出力機器に応じて比較評価する。
   - リサンプル前後の周波数応答と位相を保存し、聴感だけに依存しない回帰検証を追加する。

8. **畳み込み負荷の計測**
   - `chunksize` 4096/8192、IRタップ数、CPU使用率、XRUN、レイテンシを実機で比較する。
   - 長時間再生時のアンダーラン監視とログ収集を追加する。

9. **3002 E2Eテストの追加**
   - Ambience変更後に8002の設定値が新値になること
   - Apply後に音量が保持されること
   - 3002のAPI URLが現在ホストに追従すること
   - `/health`が正常時・MPD切断時に期待JSONを返すこと
