# 2026-05-06_project.md

## 目的
- 既存の DSP 画面と DMP 機能を、バックエンド統合なしで同一ブラウザ体験にまとめる
- 同一タブ内でワンタッチ切替し、アルバムアート下側の領域のみを入れ替える

## 見立て（実現可能性）
- 実装は十分可能
- バックエンド統合は必須ではない
- まずはフロント側シェル統合から始めるのが最小リスク

## 推奨アプローチ
- 単一 Next.js フロントで DSP/DMP をビュー切替
- ヘッダ・再生バー・アルバムアート上部は共通化
- アルバムアート下のコンテンツ領域のみ条件レンダリングで差し替え
- DSP View / DMP View のトグルボタンを常設

## 実装方式の選択肢
- 方式A: 同一フロント内コンポーネント切替（推奨）
  - 長所: UX が自然、状態共有しやすい
  - 短所: 初期設計が必要
- 方式B: DMP を iframe 埋め込み
  - 長所: 最短で動く
  - 短所: スタイル統一と状態同期が弱い
- 方式C: 同一 UI シェル + API 別系統（中間）
  - 長所: バックエンド分離を保ちつつ見た目は統一
  - 短所: API 層の取り回し設計が必要

## 重要な設計ポイント
- API 入口の統一
  - フロントからは単一オリジンに見えるように rewrite/proxy を使う
- WebSocket 管理
  - DSP 系と DMP 系を共通フック化し、切替時の接続/切断を明示管理
- 状態管理の一元化
  - 再生状態、曲情報、接続状態、表示モードを共通ストアで管理
- レイアウト分離
  - 固定領域（上）と差替領域（下）を先に分離し、実装の見通しを良くする

## 想定ステップ（最小構成）
- Step 1: 画面シェル作成（固定領域 + 差替領域）
- Step 2: DSP/DMP トグル追加
- Step 3: 差替領域へ既存 DSP コンポーネント移植
- Step 4: DMP コンポーネント接続
- Step 5: 共通状態・WS 管理の統合
- Step 6: 切替時の UX 調整（読み込み表示、復帰位置、フェード）

## 結論
- 要件の「同一タブ内ワンタッチ切替」「アルバムアート下のみ入替」は現実的
- バックエンド統合なしで段階導入できる
- 次回は最小構成の UI シェル実装から着手するのが最適
